# TunnelBar

macOS 菜单栏 SSH 隧道管理器。常驻顶部状态栏，支持配置多条隧道，面板里开关即启停；
网络中断后自动指数退避重连（1.5s → 30s 封顶，autossh 风格），稳定运行 60s 后计数清零。
认证失败、服务器身份未确认、端口占用和配置错误会暂停重试，给出处理建议。

**默认退出不会中断任何隧道**：退出/重启 TunnelBar 只停止应用内的监控和重试，
所有 SSH 进程继续独立运行，PID 文件保留。下次启动会先校准状态，再按自动启动设置拉起尚未运行的隧道：
核对可执行文件和完整参数，接管已有进程并恢复运行时长，即使该隧道没有勾选自动启动也会接管。
PID 文件丢失或失效时，自动恢复唯一且参数匹配的 SSH 进程；发现多个匹配进程时保留连接并提示，
不会额外启动。要停隧道请用面板开关或「全部停止」。

自动重连由 TunnelBar 提供；应用退出期间若 SSH 自己断开，不会在后台重连，下次启动时按配置恢复。

> ⚠️ 别在终端手动跑 TunnelBar 管理的同一条 `-L` 隧道，端口会互相冲突（ExitOnForwardFailure
> 会让后来者起不来）。每条隧道的 ssh stderr 记在 `run/<id>.log`，卡片「查看诊断」可展开查看。

```bash
./build.sh
open build/TunnelBar.app
```

## 配置

图形化配置：面板底部「配置」打开配置窗口，左侧列出分组、隧道和 SSH 节点，可搜索并用键盘选择。
右侧编辑名称、归属分组、节点、转发与高级选项；每条转发区分监听端和目标端，节点页可选择私钥文件、跳转关联隧道。
所有编辑和删除先保留在草稿中，点击「保存」或 ⌘S 才应用；保存前实时校验并列出将重连、停止或启动的隧道。
名称、归属分组与自动启动选项的修改不触发重连；修改连接参数会重启受影响的运行中隧道。
新加的 autoStart 隧道保存后立即拉起。被引用的节点无法删除；保存失败保留草稿，保存成功显示状态并继续编辑。

新建隧道时可选择 PostgreSQL、MySQL、Redis、网页访问、SOCKS 或自定义模板。
模板默认仅监听 `127.0.0.1`，推荐的本机端口会避开已有配置，目标地址与端口可继续修改。
右键隧道或点击详情标题旁的复制按钮可创建副本；副本使用独立 ID，保留分组、转发和节点设置，默认关闭自动启动。
模板和副本都先进入草稿，创建本身不连接服务器。与其他隧道重叠的监听端口会提示，仍允许保存用于交替启用。

### 项目分组

在「添加资源 → 新建分组」中创建项目，在分组页移入已有隧道或新建隧道。
也可在隧道设置中选择「所属分组」。每条隧道只属于一个分组，SSH 节点可被不同项目的隧道复用。
需要共用数据库、Redis 或代理时，可创建普通分组「公共连接」，将对应隧道放进去独立启停。
项目使用它已开放的本机端口；启动或停止项目分组不会联动公共连接。

菜单栏按配置中的顺序展示分组，末尾展示有隧道的「未分组」。组头显示已建立数量与需关注数量，
后者包括重连、需要处理和待确认。点击组名展开/收起，折叠状态仅保存在本机展示偏好中。
「启动本组」启动尚未启用的成员；「停止本组」停止本组所有成员并取消等待重连，不影响其他分组。
重命名或调整归属会保留现有连接；删除分组只将成员移到未分组，保留隧道设置和运行状态。
自动启动仍由每条隧道单独设置。分组名称不能留空、重名或使用保留名称「未分组」。

旧配置缺少分组字段时自动视为未分组，加载不会改变隧道参数或主动重写配置。

### 连接与导入

每次启动会检查明确填写的普通私钥路径，以及 L/D 规则的重复监听和本机数字地址端口占用。
检查仅临时绑定端口后释放，不连接服务；R 的远程端口、SSH 配置继承的转发和动态密钥路径由 SSH 确认。
预检通过后端口仍可能被其他程序抢占，最终状态以 SSH 建立结果为准。

快速导入节点：点击左下「从 SSH 配置导入…」（或「添加资源」中的同名操作），
搜索、多选 `~/.ssh/config` 中的具体 `Host` 别名。已有节点会标记为「已添加」并跳过；
导入只向草稿添加节点，点击保存后生效，不创建或启停隧道。
导入节点保留别名，用户、端口、私钥、`ProxyJump` 等继续由 SSH 配置提供。
支持非条件 `Include`、通配文件路径和嵌套文件；`Host *`、`Match all` 下的 Include 也会读取。
通配 Host 与否定模式不作为节点；条件 Include、动态路径或部分读取失败会在导入窗口提示。
读取过程不执行 SSH、`Match exec` 或连接服务器，也不修改 SSH 配置文件。

配置包含分组、节点和隧道，文件位于 `~/.config/tunnel-bar/config.json`（首次启动自动生成，老版
sshTarget 单串格式会自动迁移，迁移前原文件备份为 `config.json.v1.bak`）：

首次启动生成空配置，不会自动连接任何服务器；从 SSH 配置导入节点或手动添加后再创建隧道。
已有配置会继续使用，升级不会用示例替换用户设置。下面是通用数据库与 SOCKS 转发示例，需自行配置节点。

配置读取或校验失败时保留原文件和当前运行状态，并在面板显示错误；不会覆盖为默认配置。
保存失败时保留编辑草稿和现有隧道。迁移备份失败时不会回写原文件；已有备份不会覆盖，
如果需要备份不同的旧版原文件，会另存为 `config.json.v1.<UUID>.bak`。

- **节点** = SSH 端点：名称、主机（域名/IP/`~/.ssh/config` 别名）、端口、用户、密钥路径。
  主机填别名时，端口/用户/密钥留空即完全沿用别名里的定义
- **隧道** = 绑定一个节点 + 可选归属分组 + 若干条转发（L/R/D）+ 附加参数 + 自动启动
- **分组** = 项目名称和稳定 ID，用于组织与批量启停，不改变 SSH 连接参数

```json
{
  "groups": [
    { "id": "project-example", "name": "项目 A" }
  ],
  "nodes": [
    { "id": "node-example", "name": "example", "host": "example", "port": "", "user": "", "identityFile": "" }
  ],
  "tunnels": [
    {
      "id": "database-forward", "name": "数据库访问", "nodeId": "node-example",
      "groupId": "project-example",
      "forwards": [
        {"type": "L", "bind": "127.0.0.1", "port": "15432", "host": "127.0.0.1", "rport": "5432"},
        {"type": "D", "port": "1080"}
      ],
      "extraArgs": [], "autoStart": false
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `groups` | 可选分组列表，数组顺序决定展示顺序，缺省为空 |
| `group.id` / `group.name` | 稳定且唯一的 ID / 非空且不重名的分组名称 |
| `tunnel.groupId` | 可选归属分组 ID；省略或 `null` 表示未分组，非空值必须引用存在的分组 |
| `node.host` | 域名 / IP / ssh 别名；`port`/`user`/`identityFile` 留空 = 不附加对应参数 |
| `forward.type` | `L` 本地转发(-L) / `R` 远程转发(-R) / `D` 动态SOCKS(-D)，一条隧道可混搭多条 |
| `forward.*` | L/R 填 地址+端口+目标地址+目标端口（地址可留空）；D 只填端口。老版纯字符串格式自动按 L 迁移 |
| `tunnel.extraArgs` | 附加 ssh 参数（空格分隔，不支持含空格的值） |
| `tunnel.autoStart` | 应用启动时是否自动拉起 |

内置固定参数（每条隧道都会带上）：
`-N -o LogLevel=DEBUG1 -o ServerAliveInterval=15 -o ServerAliveCountMax=4 -o ExitOnForwardFailure=yes -o ConnectTimeout=10`

## 连接状态与诊断

- **连接中**：已启动 SSH，正在等待认证与转发确认；启动进程不会直接显示成功。
- **已建立**：SSH 会话与配置中的转发已确认，R 还需收到服务器的转发确认；不代表数据库、网页等目标服务已经健康。
- **重连中**：网络超时、断线等临时故障自动退避重试，可用开关取消。
- **需要处理**：认证、服务器身份、私钥、端口或配置问题暂停重试；卡片展示处理建议，修正后点击「重试连接」。
- **待确认**：接管旧版连接但缺少对应的确认记录，或运行 30 秒仍未获得完整诊断。保留进程并继续观察，不强制重启连接。

诊断记录和成功状态都与具体 PID 对应，避免旧日志误报新连接成功。新增诊断选项不会阻止接管旧版 SSH 进程。
就绪判断基于 [OpenSSH 的转发确认输出](https://github.com/openssh/openssh-portable/blob/V_10_2_P1/ssh.c)
和 [会话建立输出](https://github.com/openssh/openssh-portable/blob/V_10_2_P1/clientloop.c)。
使用 `-q`、`-E` 等附加参数改变日志输出时，可能保持「待确认」，可在卡片中查看诊断。

## 本地数据与隐私

配置、迁移备份、PID 与 SSH 错误日志仅存储在本机。应用目录和运行目录权限为 `0700`，
文件权限为 `0600`；读取旧配置时会修正应用自身文件的权限，不修改连接参数。
节点只记录私钥路径，不复制私钥内容。SSH 导入仅读取配置文件，不执行命令或上传内容。
错误日志可能包含主机、用户名和文件路径，分享前请脱敏；勿在附加参数中放置密码或 Token。
应用运行期间，已确认连接的诊断日志超过 2 MiB 时保留末尾 64 KiB；成功状态单独保留，日志截短不影响下次接管。
应用退出后暂停日志维护。展开诊断最多读取末尾 8 KiB，避免大日志阻塞面板。
仓库忽略本地配置、日志、PID、环境变量和常见私钥文件，预览工具只使用通用演示数据。

## 菜单说明

- 分组头显示已建立数量、需关注数量，支持展开/收起与独立「启动本组」「停止本组」
- 隧道卡片分别显示名称、运行状态与时长、SSH 节点、转发类型和端口路径；右侧开关启停
- 重连中显示重试次数与等待时间，「查看诊断」展开 SSH 报错；多条规则可展开，多条隧道可滚动查看
- 底部「配置」管理分组、节点与隧道；「更多」菜单提供全部启动/停止、原始配置、重新载入和退出
- **退出 app 不杀隧道**，重启后按 pid 文件自动接管恢复状态；要停隧道用面板开关

## 开机自启

系统设置 → 通用 → 登录项与扩展 → 登录项 → `+` 添加 `build/TunnelBar.app`。
（建议把 .app 挪到 `~/Applications` 等稳定位置再加入，build 目录容易被清理）

## 卸载

先在面板里「全部停止」（或手动 `pkill -f "ssh -N -L"`）→ 删掉项目目录 → `rm -rf ~/.config/tunnel-bar`
